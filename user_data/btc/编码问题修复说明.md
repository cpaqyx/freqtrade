# Windows 控制台编码问题修复

## 🐛 问题描述

### 错误信息
```
UnicodeEncodeError: 'gbk' codec can't encode character '\U0001f4c8' in position 51: illegal multibyte sequence
```

### 原因
Windows 控制台默认使用 GBK 编码，无法显示 emoji 表情符号（📈、📉、✅ 等），导致日志输出时报错。

---

## ✅ 已修复

### 修改内容

将策略文件中的所有 emoji 表情符号替换为文本标记：

| 原符号 | 新标记 | 说明 |
|--------|--------|------|
| ✅ | [OK] | 初始化成功 |
| 📈 | [BUY] | 买入信号 |
| 📉 | [SELL] | 卖出信号 |

### 修改位置

**文件**：`user_data/btc/BTCFullPosition.py`

**共修复 8 处**：
1. ✅ Line 160: 初始化日志
2. ✅ Line 186: 平仓信号 AB 高
3. ✅ Line 192: 平仓信号 AB 低
4. ✅ Line 203: 平仓信号 AC 高
5. ✅ Line 209: 平仓信号 AC 低
6. ✅ Line 298: 买入条件 2.1
7. ✅ Line 314: 买入条件 2.2 (flat)
8. ✅ Line 325: 买入条件 2.2 (小up)

## 📝 注意事项

### 为什么不修改启动脚本的编码设置？

虽然可以通过设置环境变量强制使用 UTF-8：
```batch
set PYTHONIOENCODING=utf-8
```

但这种方法：
- ❌ 可能在某些 Windows 版本失效
- ❌ 可能影响其他输出
- ❌ 不够稳定

**推荐方案**：
- ✅ 直接修改代码，避免使用 emoji
- ✅ 使用纯文本标记，兼容性更好
- ✅ 更加稳定可靠

### 如果需要使用 emoji

如果确实需要在日志中使用 emoji，可以：

1. **配置日志输出到文件**（推荐）
   ```python
   # 在 config.json 中设置
   "logfile": "user_data/logs/btc_live.log"
   ```
   文件日志支持 UTF-8 编码，可以正确显示 emoji

2. **使用 Windows Terminal**
   - 下载并安装 Windows Terminal
   - 默认支持 UTF-8 编码
   - 可以正确显示 emoji

3. **修改控制台代码页**
   ```batch
   chcp 65001  # 切换到 UTF-8
   ```
   但可能导致其他显示问题
